# 任务拆分器设计

## 一、概述

将任务拆分为子任务列表，支持不同任务类型的拆分策略。

**职责边界**：
- 只关注子任务创建，不关注依赖关系（由 DAGBuilder 处理）
- 不关注存储和事件发布（由 TaskManager 处理）

---

## 二、结构与数据模型

### 2.1 SplitStrategy（策略接口）

```go
type SplitStrategy interface {
    Split(task *Task) ([]*SubTask, error)
}
```

### 2.2 TaskSplitter（拆分器）

```go
type TaskSplitter struct {
    strategies map[string]SplitStrategy  // taskType → 策略
    logger     *zap.Logger
}
```

| 方法 | 说明 |
|------|------|
| RegisterStrategy(taskType, strategy) | 注册拆分策略 |
| Split(task) ([]*SubTask, error) | 拆分任务 |

---

## 三、核心逻辑

```go
func (s *TaskSplitter) Split(task *Task) ([]*SubTask, error) {
    // 1. 根据 task.Type 获取策略
    strategy := s.strategies[task.Type]

    // 2. 调用策略拆分
    subTasks := strategy.Split(task)

    // 3. 设置子任务的 type 字段（继承任务类型）
    for _, subTask := range subTasks {
        subTask.Type = task.Type
    }

    return subTasks, nil
}
```

## 四、扩展与集成

### 4.1 内置策略

| 任务类型 | 策略 | 拆分规则 |
|----------|------|----------|
| agent_eval | AgentEvalSplitStrategy | synthesis(1) + inference(N) + eval(N) + report(1) |
| model_eval | ModelEvalSplitStrategy | inference(N) + eval(N) + report(1) |

**AgentEval 拆分流程**：

```
1. synthesis    → 1个子任务（workflow包含synthesis时）
2. case循环     → 每个case: inference + eval
3. report       → 1个子任务（workflow包含report时）
```

**ModelEval 拆分流程**：

```
1. case循环     → 每个case: inference + eval（无synthesis）
2. report       → 1个子任务（必有）
```

### 4.2 扩展方式

```go
// 1. 定义策略
type SafetyEvalSplitStrategy struct{}

func (s *SafetyEvalSplitStrategy) Split(task *Task) ([]*SubTask, error) {
    // 实现拆分逻辑
}

// 2. 注册
splitter.RegisterStrategy("safety_eval", &SafetyEvalSplitStrategy{})
```

### 4.3 与 DAGBuilder 协作

| 步骤 | 模块 | 输出 |
|------|------|------|
| 1. Split | TaskSplitter | SubTask 列表 |
| 2. Build | DAGBuilder | DAGNode 列表（定义依赖） |
| 3. Persist | TaskManager | 持久化到 Storage |
