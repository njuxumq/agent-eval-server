# 数据模型设计文档

## 一、概述

### 1.1 文档目的

本文档定义应用评测服务（agent-eval-server）的 MongoDB 数据模型，包括：
- 各 Collection 的表结构设计
- 字段类型与约束定义
- 索引设计
- 状态枚举定义

### 1.2 设计原则

| 原则 | 说明 |
|------|------|
| **通用性** | 支持多种评测类型（模型评测、应用评测），配置使用原始存储 |
| **一致性** | 状态枚举统一，字段命名规范 |
| **可扩展** | 使用 map[string]interface{} 支持灵活配置 |
| **高性能** | 索引覆盖高频查询场景，避免全表扫描 |
| **并发安全** | 关键状态字段支持原子更新，避免竞态条件 |
| **配置分离** | 任务配置独立存储，任务表只存通用状态信息 |
| **阶段独立** | 阶段表独立管理，支持不同评测类型的阶段差异 |
| **简化设计** | 移除 DAGNode 中间层，直接通过阶段统计子任务完成状态 |

### 1.3 数据库概述

| Collection | 说明 | 所属层次 |
|------------|------|----------|
| `tasks` | 任务通用状态信息 | 任务层 |
| `task_configs` | 任务配置（独立存储） | 任务层 |
| `stages` | 阶段任务（预拆分） | 阶段层 |
| `subtasks` | 子任务记录（阶段启动时拆分） | 执行层 |
| `master_state` | 主从状态 | 系统层 |

## 二、状态枚举定义

本节统一定义各层次实体的状态枚举，确保状态语义一致。

### 2.1 任务状态（TaskStatus）

| 值 | 名称 | 说明 |
|----|------|------|
| 0 | Waiting | 等待中（等待初始化或等待资源） |
| 1 | Running | 执行中 |
| 2 | Finished | 执行完成 |
| 3 | Failed | 任务失败 |
| 4 | Canceled | 任务取消 |
| 5 | Exception | 异常（中间态，可重试） |

**状态转换路径**：
```
Waiting → Running → Finished
                ↘ Failed
                ↘ Exception → Running (重试)
Waiting/Running/Exception → Canceled (用户取消)
```

### 2.2 阶段状态（StageStatus）

| 值 | 名称 | 说明 |
|----|------|------|
| 0 | Pending | 待执行 |
| 1 | Running | 执行中 |
| 2 | Completed | 完成 |
| 3 | Failed | 失败 |
| 4 | Skipped | 跳过（如用户已提供评测集时跳过synthesis） |

**状态转换路径**：
```
Pending → Running → Completed
              ↘ Failed
Pending → Skipped (条件跳过)
```

### 2.3 子任务状态（SubTaskStatus）

| 值 | 名称 | 说明 |
|----|------|------|
| 0 | Pending | 待分发 |
| 1 | Allocated | 已分配执行服务（等待执行） |
| 2 | Running | 执行中 |
| 3 | Finished | 完成 |
| 4 | Failed | 失败（不可重试） |
| 5 | Exception | 异常（可重试） |
| 6 | Canceled | 取消 |

**状态转换路径**：
```
Pending → Allocated → Running → Finished
                              ↘ Failed
                              ↘ Exception → Allocated (重试)
Pending/Allocated/Running → Canceled (任务取消)
```

## 三、任务数据模型

任务层是数据模型的顶层，包含任务主表（通用状态）和配置表（独立存储）。

### 3.1 任务主表（tasks）

#### 3.1.1 设计思路

任务表只存储**通用状态信息**，不存储具体配置：
- 任务标识、类型、应用标识
- 任务生命周期状态、进度、消息
- 当前阶段信息
- 评测结果汇总
- 时间戳信息

#### 3.1.2 表结构

```javascript
{
  "_id": ObjectId,                          // MongoDB自动生成
  "task_id": String,                        // 任务唯一标识（业务主键）
  "app_id": String,                         // 应用标识
  "type": String,                           // 任务类型：model_eval / agent_eval
  "description": String,                    // 任务描述（可选）
  
  // ===== 状态信息 =====
  "status": Int32,                          // 任务状态（枚举）
  "progress": Int32,                        // 执行进度 0-100
  "message": String,                        // 状态消息
  
  // ===== 当前阶段信息 =====
  "current_stage": Int32,                   // 当前执行阶段编号（stage_id，0-based）
  "current_stage_type": String,             // 当前阶段类型（可选，用于展示）
  
  // ===== 评测结果汇总 =====
  "result": {                               // 评测结果汇总（嵌入文档）
    "success": Int32,                       // 执行结果：1成功 / -1失败
    "message": String,                      // 失败信息
    "progress": Int32,                      // 进度 0-100
    "report_url": String,                   // 评测报告URL
    "usages": [{                            // Token消耗统计
      "model_id": String,
      "input_tokens": Int32,
      "output_tokens": Int32
    }]
  },
  
  // ===== 时间戳 =====
  "created_at": Int64,                      // 创建时间（Unix时间戳）
  "updated_at": Int64,                      // 更新时间（Unix时间戳）
  "expired_at": Int64                       // 过期时间（Unix时间戳，可选）
}
```

#### 3.1.3 字段说明

| 字段 | 类型 | 必填 | 说明 | 约束 |
|------|------|------|------|------|
| `task_id` | String | 是 | 任务唯一标识 | UUID格式，唯一索引 |
| `app_id` | String | 是 | 应用标识 | 用于权限校验，索引 |
| `type` | String | 是 | 任务类型 | 枚举：model_eval / agent_eval |
| `description` | String | 否 | 任务描述 | 最大200字符 |
| `status` | Int32 | 是 | 任务状态 | 枚举值：0-5 |
| `progress` | Int32 | 是 | 执行进度 | 0-100 |
| `message` | String | 否 | 状态消息 | 最大200字符 |
| `current_stage` | Int32 | 否 | 当前阶段编号 | stage_id (0-based) |
| `current_stage_type` | String | 否 | 当前阶段类型 | 用于展示 |
| `result` | Object | 否 | 评测结果 | 仅完成状态填充 |
| `created_at` | Int64 | 是 | 创建时间 | Unix秒级时间戳 |
| `updated_at` | Int64 | 是 | 更新时间 | Unix秒级时间戳 |
| `expired_at` | Int64 | 否 | 过期时间 | 用于数据清理 |

#### 3.1.4 索引设计

| 索引名 | 字段 | 类型 | 说明 |
|--------|------|------|------|
| `idx_task_id` | `task_id` | 唯一 | 业务主键查询 |
| `idx_app_id` | `app_id` | 普通 | 按应用查询任务列表 |
| `idx_app_status` | `app_id` + `status` | 复合 | 按应用和状态筛选任务 |
| `idx_created_at` | `created_at` | 普通 | 按时间排序查询 |
| `idx_status_updated` | `status` + `updated_at` | 复合 | 状态监控、过期清理 |

#### 3.1.5 查询场景

| 场景 | 查询条件 | 使用索引 |
|------|----------|----------|
| 任务详情查询 | `task_id` | `idx_task_id` |
| 任务列表查询 | `app_id` + `status` + 排序 | `idx_app_status` + `idx_created_at` |
| 任务状态监控 | `status` ∈ {Running, Waiting, Exception} | `idx_status_updated` |
| 过期数据清理 | `expired_at` < 当前时间 | 全表扫描（低频） |

### 3.2 任务配置表（task_configs）

#### 3.2.1 设计思路

任务配置**独立存储**，按任务类型动态解析：
- 关联任务ID
- 存储原始配置（动态结构）
- 支持按类型解析为不同配置结构

#### 3.2.2 表结构

```javascript
{
  "_id": ObjectId,                          // MongoDB自动生成
  "task_id": String,                        // 关联任务ID
  "type": String,                           // 任务类型（与tasks.type一致）
  
  // ===== 原始配置 =====
  "config": Object,                         // 原始配置（动态结构）
  
  // ===== 解析后的配置（可选，用于缓存） =====
  "parsed_config": Object,                  // 解析后的配置结构
  
  // ===== 时间戳 =====
  "created_at": Int64                       // 创建时间
}
```

#### 3.2.3 字段说明

| 字段 | 类型 | 必填 | 说明 | 约束 |
|------|------|------|------|------|
| `task_id` | String | 是 | 关联任务ID | 关联tasks表，唯一索引 |
| `type` | String | 是 | 任务类型 | 枚举：model_eval / agent_eval |
| `config` | Object | 是 | 原始配置 | 动态结构，按type解析 |
| `parsed_config` | Object | 否 | 解析后配置 | 可选缓存 |
| `created_at` | Int64 | 是 | 创建时间 | Unix秒级时间戳 |

#### 3.2.4 配置类型说明

**按 type 解析为不同结构**：

| type | 配置结构 | 说明 |
|-----|---------|------|
| `model_eval` | ModelEvalConfig | 模型评测配置 |
| `agent_eval` | AgentEvalConfig | 应用评测配置 |

**AgentEvalConfig 核心字段**：

```json
{
  "version": "2.0.0",
  "config": {
    "models": [...],
    "agents": [...],
    "skills": [
      {
        "type": "s3",
        "url": "https://storage.example.com/skills/skill-v1.zip"
      }
    ]
  },
  "execution": {
    "workflow": ["synthesis", "inference", "eval", "report"],
    "models": [...],
    "synthesis": {阶段配置},
    "inference": {阶段配置},
    "eval": {阶段配置},
    "report": {阶段配置},
    "resources": {
      "type": "s3",
      "url": "https://storage.example.com/resources/resource-1.zip"
    }
  }
}
```

### 3.3 任务初始化事务

创建任务时，需同时写入 Task、TaskConfig、Stage记录：

```javascript
session.startTransaction()

try {
  db.tasks.insertOne(taskDoc, {session})
  db.task_configs.insertOne(taskConfigDoc, {session})
  db.stages.insertMany(stageDocs, {session})
  session.commitTransaction()
} catch (error) {
  session.abortTransaction()
  throw error
}
```

## 四、阶段数据模型

阶段层是任务和执行单元的中间层，管理任务的阶段性执行。

### 4.1 阶段表（stages）

#### 4.1.1 设计思路

阶段表**通用抽象**，作为任务和子任务的中间层：
- 关联任务ID
- 存储阶段类型、状态、进度
- 存储阶段配置（从任务配置中提取）
- 支持阶段跳过（如用户已提供评测集）

#### 4.1.2 表结构

```javascript
{
  "_id": ObjectId,                          // MongoDB自动生成
  "stage_id": Int32,                        // 阶段顺序编号（0-based）
  "task_id": String,                        // 所属任务ID
  "stage_type": String,                     // 阶段类型（synthesis/inference/eval/report）

  // ===== 阶段配置 =====
  "config": Object,                         // 阶段配置（从任务配置提取）

  // ===== 状态信息 =====
  "status": Int32,                          // 阶段状态（枚举）
  "progress": Int32,                        // 阶段进度 0-100
  "message": String,                        // 状态消息

  // ===== 子任务统计 =====
  "total_count": Int32,                     // 阶段子任务总数
  "completed_count": Int32,                 // 已完成子任务数
  "failed_count": Int32,                    // 失败子任务数

  // ===== 时间戳 =====
  "created_at": Int64,                      // 创建时间
  "started_at": Int64,                      // 开始时间（可选）
  "completed_at": Int64                     // 完成时间（可选）
}
```

#### 4.1.3 字段说明

| 字段 | 类型 | 必填 | 说明 | 约束 |
|------|------|------|------|------|
| `stage_id` | Int32 | 是 | 阶段顺序编号 | 0-based，与 task_id 组成联合唯一键 |
| `task_id` | String | 是 | 所属任务ID | 关联tasks表，索引 |
| `stage_type` | String | 是 | 阶段类型 | 枚举：synthesis/inference/eval/report |
| `config` | Object | 是 | 阶段配置 | 从任务配置提取 |
| `status` | Int32 | 是 | 阶段状态 | 枚举值：0-4 |
| `progress` | Int32 | 是 | 阶段进度 | 0-100 |
| `message` | String | 否 | 状态消息 | 最大200字符 |
| `total_count` | Int32 | 是 | 子任务总数 | 阶段启动时更新 |
| `completed_count` | Int32 | 是 | 已完成数 | 默认0 |
| `failed_count` | Int32 | 是 | 失败数 | 默认0 |
| `created_at` | Int64 | 是 | 创建时间 | Unix秒级时间戳 |
| `started_at` | Int64 | 否 | 开始时间 | Unix秒级时间戳 |
| `completed_at` | Int64 | 否 | 完成时间 | Unix秒级时间戳 |

#### 4.1.4 阶段类型说明

**应用评测阶段**：

| stage_type | 说明 | 子任务数量 |
|-----------|------|----------|
| `synthesis` | 评测集合成 | 1 |
| `inference` | Agent推理执行 | M × N |
| `eval` | 评测执行 | M × N |
| `report` | 报告生成 | 1 |

**模型评测阶段**：

| stage_type | 说明 | 子任务数量 |
|-----------|------|----------|
| `inference` | Agent调用执行 | M |
| `eval` | 评测执行 | M |
| `report` | 报告生成 | 1 |

#### 4.1.5 索引设计

| 索引名 | 字段 | 类型 | 说明 |
|--------|------|------|------|
| `idx_task_stage` | `task_id` + `stage_id` | 联合唯一 | 业务主键查询 |
| `idx_task_id` | `task_id` | 普通 | 按任务查询阶段列表 |
| `idx_task_status` | `task_id` + `status` | 复合 | 查询阶段状态 |

#### 4.1.6 查询场景

| 场景 | 查询条件 | 使用索引 |
|------|----------|----------|
| 阶段详情查询 | `task_id` + `stage_id` | `idx_task_stage` |
| 任务阶段列表 | `task_id` | `idx_task_id` |
| 当前阶段查询 | `task_id` + `stage_id` = current | `idx_task_stage` |
| 阶段状态查询 | `task_id` + `status` | `idx_task_status` |

#### 4.1.7 原子操作

**阶段统计原子更新**：

```javascript
// 已完成计数递增
db.stages.updateOne(
  {"stage_id": "stage-001"},
  {
    $inc: {"completed_count": 1},
    $set: {"updated_at": 1761983700}
  }
)
```

### 4.2 阶段启动事务

阶段启动时，需同时写入 SubTask 记录并更新阶段状态：

```javascript
session.startTransaction()

try {
  db.subtasks.insertMany(subtaskDocs, {session})
  db.stages.updateOne(
    {"task_id": taskId, "stage_id": stageId},
    {$set: {"total_count": subtaskDocs.length, "status": 1}},
    {session}
  )
  session.commitTransaction()
} catch (error) {
  session.abortTransaction()
  throw error
}
```

## 五、执行单元数据模型

执行层包含子任务表（具体执行单元）。

### 5.1 子任务表（subtasks）

#### 5.1.1 设计思路

子任务表采用**通用结构**设计：
- 关联任务ID、阶段ID
- 存储子任务类型（task_type + stage_type）
- 变化信息统一存储在 input.variant 字段下
- 存储执行状态、结果
- 支持重试机制

#### 5.1.2 表结构

```javascript
{
  "_id": ObjectId,                          // MongoDB自动生成
  "subtask_id": String,                     // 子任务唯一标识（业务主键）
  "task_id": String,                        // 所属任务ID
  "stage_id": Int32,                        // 所属阶段编号（0-based）

  // ===== 子任务类型 =====
  "task_type": String,                      // 任务类型（agent_eval/model_eval）
  "stage_type": String,                     // 阶段类型（synthesis/inference/eval/report）
  
  // ===== 执行参数 =====
  "input": {                                // 执行参数（嵌入文档）
    "command": String,                      // 执行命令
    "args": [String],                       // 命令参数
    "envs": Object,                         // 环境变量
    "input_files": [{                       // 输入文件
      "name": String,                       // 文件名/路径
      "url": String                         // 文件URL（从数据管理服务获取）
    }],
    "output_specs": [{                      // 输出规格
      "name": String                        // 期望输出的文件名
    }],
    "timeout_sec": Int64,                   // 超时时间
    
    // ===== 类型特定参数（动态结构，按stage_type解析） =====
    "variant": Object                       // 变体参数（inference/eval阶段）
                                            // - evalset_index: Int32
                                            // - variant_index: Int32
                                            // - variant_type: String
                                            // - variant_id: String
                                            // synthesis/report阶段此字段为空
  },
  
  // ===== 执行状态 =====
  "executor": String,                       // 执行服务地址
  "sandbox_id": String,                     // 沙箱ID
  "status": Int32,                          // 子任务状态（枚举）
  "retry_count": Int32,                     // 重试次数
  
  // ===== 执行结果 =====
  "result": {                               // 执行结果（嵌入文档）
    "success": Int32,                       // 执行结果：1成功 / -1失败
    "message": String,                      // 失败信息
    "progress": Int32,                      // 进度 0-100
    "output_files": [String],               // 输出文件URL列表
    "output_refs": {                        // 输出数据引用
      "evalset_id": String,                 // 评测集ID（synthesis阶段）
      "evalset_count": Int32,               // 评测集数量（synthesis阶段）
      "record_id": String                   // 评测记录ID（inference/eval阶段）
    },
    "usages": [{                            // Token消耗
      "model_id": String,
      "input_tokens": Int32,
      "output_tokens": Int32
    }]
  },
  
  // ===== 时间戳 =====
  "created_at": Int64,                      // 创建时间
  "started_at": Int64,                      // 开始时间（可选）
  "completed_at": Int64                     // 完成时间（可选）
}
```

#### 5.1.3 字段说明

| 字段 | 类型 | 必填 | 说明 | 约束 |
|------|------|------|------|------|
| `subtask_id` | String | 是 | 子任务唯一标识 | UUID格式，唯一索引 |
| `task_id` | String | 是 | 所属任务ID | 关联tasks表，索引 |
| `stage_id` | Int32 | 是 | 所属阶段编号 | 0-based，与 task_id 组成联合键 |
| `task_type` | String | 是 | 任务类型 | 枚举：agent_eval/model_eval |
| `stage_type` | String | 是 | 阶段类型 | 枚举：synthesis/inference/eval/report |
| `input` | Object | 是 | 执行参数 | 执行服务直接使用 |
| `executor` | String | 否 | 执行服务地址 | 分配后填充 |
| `sandbox_id` | String | 否 | 沙箱ID | 执行后填充 |
| `status` | Int32 | 是 | 子任务状态 | 枚举值：0-6 |
| `retry_count` | Int32 | 是 | 重试次数 | 默认0，最大3 |
| `result` | Object | 否 | 执行结果 | 完成后填充 |
| `created_at` | Int64 | 是 | 创建时间 | Unix秒级时间戳 |
| `started_at` | Int64 | 否 | 开始时间 | Unix秒级时间戳 |
| `completed_at` | Int64 | 否 | 完成时间 | Unix秒级时间戳 |

#### 5.1.4 input.variant 字段说明

**variant 字段按 stage_type 动态解析**：

| stage_type | variant 字段内容 | 说明 |
|-----------|-----------------|------|
| `synthesis` | 空 {} | synthesis阶段无变体参数 |
| `inference` | evalset_index, variant_index, variant_type, variant_id | 评测集索引 + 变体信息 |
| `eval` | evalset_index, variant_index, variant_type, variant_id | 同inference阶段 |
| `report` | 空 {} | report阶段无变体参数 |

#### 5.1.5 索引设计

| 索引名 | 字段 | 类型 | 说明 |
|--------|------|------|------|
| `idx_subtask_id` | `subtask_id` | 唯一 | 业务主键查询 |
| `idx_task_id` | `task_id` | 普通 | 按任务查询子任务列表 |
| `idx_task_stage` | `task_id` + `stage_id` | 复合 | 按阶段查询子任务列表 |
| `idx_status` | `status` | 普通 | 状态监控查询 |
| `idx_executor_status` | `executor` + `status` | 复合 | 执行服务负载查询 |

#### 5.1.6 查询场景

| 场景 | 查询条件 | 使用索引 |
|------|----------|----------|
| 子任务详情查询 | `subtask_id` | `idx_subtask_id` |
| 任务子任务列表 | `task_id` | `idx_task_id` |
| 阶段子任务列表 | `task_id` + `stage_id` | `idx_task_stage` |
| 执行服务负载查询 | `executor` + `status` ∈ {Allocated, Running} | `idx_executor_status` |
| 异常子任务查询 | `status` = Exception | `idx_status` |

#### 5.1.7 原子操作

**SubTask状态更新**：

```javascript
// 从Allocated更新为Running（需检查当前状态）
db.subtasks.updateOne(
  {
    "subtask_id": "subtask-001",
    "status": 1  // 确保当前状态为Allocated
  },
  {$set: {"status": 2, "updated_at": 1761983700}}
)
```

**重试计数原子更新**：

```javascript
// 重试计数递增
db.subtasks.updateOne(
  {"subtask_id": "subtask-001"},
  {
    $inc: {"retry_count": 1},
    $set: {"status": 5, "updated_at": 1761983700}
  }
)
```

## 六、系统数据模型

系统层包含主从状态表，用于调度服务的高可用管理。

### 6.1 主从状态表（master_state）

#### 6.1.1 设计思路

主从状态表用于调度服务的高可用：
- 记录调度服务节点角色
- 心跳时间戳用于故障检测
- 支持主从切换

#### 6.1.2 表结构

```javascript
{
  "_id": ObjectId,                          // MongoDB自动生成
  "node_id": String,                        // 调度服务节点标识
  "role": String,                           // 角色：master/slave
  "last_heartbeat": Int64,                  // 最后心跳时间
  "updated_at": Int64                       // 更新时间
}
```

#### 6.1.3 字段说明

| 字段 | 类型 | 必填 | 说明 | 约束 |
|------|------|------|------|------|
| `node_id` | String | 是 | 调度服务节点标识 | 唯一，主机名或UUID |
| `role` | String | 是 | 角色 | 枚举：master/slave |
| `last_heartbeat` | Int64 | 是 | 最后心跳时间 | Unix秒级时间戳 |
| `updated_at` | Int64 | 是 | 更新时间 | Unix秒级时间戳 |

#### 6.1.4 索引设计

| 索引名 | 字段 | 类型 | 说明 |
|--------|------|------|------|
| `idx_node_id` | `node_id` | 唯一 | 节点标识唯一性 |
| `idx_role` | `role` | 普通 | 查询当前master |

#### 6.1.5 原子操作

**Master心跳原子更新**：

```javascript
// Master心跳更新（带角色校验）
db.master_state.updateOne(
  {
    "node_id": "scheduler-node-01",
    "role": "master"  // 确保自己是master
  },
  {$set: {"last_heartbeat": 1761983700, "updated_at": 1761983700}}
)
```

## 七、跨层事务

跨层事务涉及多个数据层次的状态联动更新。

### 7.1 任务取消事务

取消任务时，需联动更新 Task、Stage、SubTask 状态：

```javascript
session.startTransaction()

try {
  db.tasks.updateOne(
    {"task_id": taskId, "status": {$in: [0, 1, 5]}},
    {$set: {"status": 4, "updated_at": now}},
    {session}
  )
  db.stages.updateMany(
    {"task_id": taskId, "status": {$in: [0, 1]}},
    {$set: {"status": 3, "updated_at": now}},
    {session}
  )
  db.subtasks.updateMany(
    {"task_id": taskId, "status": {$in: [0, 1, 2]}},
    {$set: {"status": 6, "updated_at": now}},
    {session}
  )
  session.commitTransaction()
} catch (error) {
  session.abortTransaction()
  throw error
}
```

## 八、数据生命周期

### 8.1 数据保留策略

| 数据类型 | 保留周期 | 说明 |
|----------|----------|------|
| Finished/Failed任务 | 7天 | 用户查询报告后可清理 |
| Canceled任务 | 3天 | 取消任务快速清理 |
| Running任务数据 | 不清理 | 任务执行期间保留 |
| Stage/SubTask | 与Task同步清理 | 随任务一起清理 |
| TaskConfig | 与Task同步清理 | 随任务一起清理 |
| MasterState | 永久保留 | 调度服务运行期间保留 |

### 8.2 清理机制

```javascript
// 清理过期的已完成任务
db.tasks.deleteMany({
  "status": {$in: [2, 3, 4]},
  "expired_at": {$lt: Date.now() / 1000}
})

// 清理对应的配置、阶段、子任务
const deletedTaskIds = [...] // 已删除的任务ID列表

db.task_configs.deleteMany({"task_id": {$in: deletedTaskIds}})
db.stages.deleteMany({"task_id": {$in: deletedTaskIds}})
db.subtasks.deleteMany({"task_id": {$in: deletedTaskIds}})
```
