# 数据模型设计文档

## 一、概述

### 1.1 文档目的

本文档定义应用评测服务（agent-eval-server）的 MongoDB 数据模型，包括：
- 各 Collection 的表结构设计
- 字段类型与约束定义
- 索引设计
- 状态枚举定义

### 1.2 设计原则

| 原则 | 说明 |
|------|------|
| **通用性** | 支持多种评测类型（模型评测、应用评测），配置使用原始存储 |
| **一致性** | 状态枚举统一，字段命名规范 |
| **可扩展** | 使用 map[string]interface{} 支持灵活配置 |
| **高性能** | 索引覆盖高频查询场景，避免全表扫描 |
| **并发安全** | 关键状态字段支持原子更新，避免竞态条件 |

### 1.3 数据库概述

| Collection | 说明 | 主要操作 |
|------------|------|----------|
| `tasks` | 任务记录 | CRUD、状态更新、进度查询 |
| `subtasks` | 子任务记录 | 创建、状态更新、按任务查询 |
| `dag_nodes` | DAG节点记录 | 创建、状态更新、依赖查询 |
| `master_state` | 主从状态 | 心跳更新、角色切换 |

## 二、状态枚举定义

### 2.1 任务状态（TaskStatus）

| 值 | 名称 | 说明 |
|----|------|------|
| 0 | Waiting | 等待中（等待拆分或等待资源） |
| 1 | Running | 执行中 |
| 2 | Finished | 执行完成 |
| 3 | Failed | 任务失败 |
| 4 | Canceled | 任务取消 |
| 5 | Exception | 异常（中间态，可重试） |

### 2.2 子任务状态（SubTaskStatus）

| 值 | 名称 | 说明 |
|----|------|------|
| 0 | Pending | 待分发 |
| 1 | Allocated | 已分配执行服务（等待执行） |
| 2 | Running | 执行中 |
| 3 | Finished | 完成 |
| 4 | Failed | 失败（不可重试） |
| 5 | Exception | 异常（可重试） |
| 6 | Canceled | 取消 |

### 2.3 DAG节点状态（DAGNodeStatus）

| 值 | 名称 | 说明 |
|----|------|------|
| 0 | Blocked | 阻塞（依赖节点未完成） |
| 1 | Ready | 就绪（依赖节点已完成，可调度） |
| 2 | Running | 运行中（子任务正在执行） |
| 3 | Finished | 完成（所有子任务完成） |
| 4 | Failed | 失败（有子任务失败） |

## 三、tasks 表设计

### 3.1 表结构

```javascript
{
  "_id": ObjectId,                          // MongoDB自动生成
  "task_id": String,                        // 任务唯一标识（业务主键）
  "app_id": String,                         // 应用标识
  "type": String,                           // 任务类型：model_eval / agent_eval
  "config": Object,                         // 原始配置（动态结构）
  "status": Int32,                          // 任务状态（枚举）
  "progress": Int32,                        // 执行进度 0-100
  "message": String,                        // 状态消息
  "result": {                               // 评测结果汇总（嵌入文档）
    "success": Int32,                       // 执行结果：1成功 / -1失败
    "message": String,                      // 失败信息
    "progress": Int32,                      // 进度 0-100
    "report_url": String,                   // 评测报告URL
    "usages": [{                            // Token消耗统计
      "model_id": String,
      "input_tokens": Int32,
      "output_tokens": Int32
    }]
  },
  "created_at": Int64,                      // 创建时间（Unix时间戳）
  "updated_at": Int64,                      // 更新时间（Unix时间戳）
  "expired_at": Int64                       // 过期时间（Unix时间戳，可选）
}
```

### 3.2 字段说明

| 字段 | 类型 | 必填 | 说明 | 约束 |
|------|------|------|------|------|
| `task_id` | String | 是 | 任务唯一标识 | UUID格式，唯一索引 |
| `app_id` | String | 是 | 应用标识 | 用于权限校验，索引 |
| `type` | String | 是 | 任务类型 | 枚举：model_eval / agent_eval |
| `config` | Object | 是 | 原始配置 | 动态结构，按type解析 |
| `status` | Int32 | 是 | 任务状态 | 枚举值：0-5 |
| `progress` | Int32 | 是 | 执行进度 | 0-100 |
| `message` | String | 否 | 状态消息 | 最大200字符 |
| `result` | Object | 否 | 评测结果 | 仅完成状态填充 |
| `created_at` | Int64 | 是 | 创建时间 | Unix秒级时间戳 |
| `updated_at` | Int64 | 是 | 更新时间 | Unix秒级时间戳 |
| `expired_at` | Int64 | 否 | 过期时间 | 用于数据清理 |

### 3.3 索引设计

| 索引名 | 字段 | 类型 | 说明 |
|--------|------|------|------|
| `idx_task_id` | `task_id` | 唯一 | 业务主键查询 |
| `idx_app_id` | `app_id` | 普通 | 按应用查询任务列表 |
| `idx_app_status` | `app_id` + `status` | 复合 | 按应用和状态筛选任务 |
| `idx_created_at` | `created_at` | 普通 | 按时间排序查询 |
| `idx_status_updated` | `status` + `updated_at` | 复合 | 状态监控、过期清理 |

## 四、subtasks 表设计

### 4.1 表结构

```javascript
{
  "_id": ObjectId,                          // MongoDB自动生成
  "sub_task_id": String,                    // 子任务唯一标识（业务主键）
  "task_id": String,                        // 所属任务ID
  "type": String,                           // 任务类型（agent_eval/model_eval）
  "sub_type": String,                       // 子任务阶段类型（synthesis/inference/eval/report）
  "extra": Object,                          // 子任务特定信息（动态结构）
  "input": {                                // 执行参数（嵌入文档）
    "command": String,                      // 执行命令
    "args": [String],                       // 命令参数
    "envs": Object,                         // 环境变量
    "input_files": [{                       // 输入文件
      "name": String,                       // 文件名/路径
      "content": BinData                    // 文件内容
    }],
    "output_specs": [{                      // 输出规格
      "name": String                        // 期望输出的文件名
    }],
    "timeout_sec": Int64                    // 超时时间
  },
  "executor": String,                       // 执行服务地址
  "slot_id": String,                        // 槽位/沙箱ID
  "status": Int32,                          // 子任务状态（枚举）
  "retry_count": Int32,                     // 重试次数
  "result": {                               // 执行结果（嵌入文档）
    "success": Int32,                       // 执行结果：1成功 / 0执行中 / -1失败
    "message": String,                      // 失败信息
    "progress": Int32,                      // 进度 0-100
    "report_url": String,                   // 报告URL
    "usages": [{                            // Token消耗
      "model_id": String,
      "input_tokens": Int32,
      "output_tokens": Int32
    }],
    "output_files": [String]                // 输出文件路径/URL列表
  },
  "created_at": Int64,                      // 创建时间
  "updated_at": Int64                       // 更新时间
}
```

### 4.2 字段说明

| 字段 | 类型 | 必填 | 说明 | 约束 |
|------|------|------|------|------|
| `sub_task_id` | String | 是 | 子任务唯一标识 | UUID格式，唯一索引 |
| `task_id` | String | 是 | 所属任务ID | 关联tasks表，索引 |
| `type` | String | 是 | 任务类型 | 枚举：agent_eval/model_eval，用于 Registry 选择 Handler |
| `sub_type` | String | 是 | 子任务阶段类型 | synthesis/inference/eval/report |
| `extra` | Object | 否 | 子任务特定信息 | 动态结构 |
| `input` | Object | 是 | 执行参数 | 执行服务直接使用 |
| `executor` | String | 否 | 执行服务地址 | 分配后填充 |
| `slot_id` | String | 否 | 槽位/沙箱ID | 执行后填充 |
| `status` | Int32 | 是 | 子任务状态 | 枚举值：0-6 |
| `retry_count` | Int32 | 是 | 重试次数 | 默认0，最大3 |
| `result` | Object | 否 | 执行结果 | 完成后填充 |
| `created_at` | Int64 | 是 | 创建时间 | Unix秒级时间戳 |
| `updated_at` | Int64 | 是 | 更新时间 | Unix秒级时间戳 |

### 4.3 子任务类型说明

**type 与 sub_type 的关系**：

| type | sub_type | 说明 |
|------|----------|------|
| agent_eval | synthesis | 应用评测-评测集合成 |
| agent_eval | inference | 应用评测-Agent推理执行 |
| agent_eval | eval | 应用评测-评测执行 |
| agent_eval | report | 应用评测-报告生成 |
| model_eval | inference | 模型评测-Agent调用执行 |
| model_eval | eval | 模型评测-评测执行 |
| model_eval | report | 模型评测-报告生成 |

**设计说明**：
- `type` 用于执行服务 Registry 选择对应的 SubTaskHandler
- `sub_type` 用于标识子任务的执行阶段
- 组合键 `(type, sub_type)` 决定具体的资源准备、命令执行、结果收集逻辑

### 4.4 索引设计

| 索引名 | 字段 | 类型 | 说明 |
|--------|------|------|------|
| `idx_sub_task_id` | `sub_task_id` | 唯一 | 业务主键查询 |
| `idx_task_id` | `task_id` | 普通 | 按任务查询子任务列表 |
| `idx_status` | `status` | 普通 | 状态监控查询 |
| `idx_executor_status` | `executor` + `status` | 复合 | 执行服务负载查询 |

## 五、dag_nodes 表设计

### 5.1 表结构

```javascript
{
  "_id": ObjectId,                          // MongoDB自动生成
  "node_id": String,                        // 节点唯一标识（业务主键）
  "task_id": String,                        // 所属任务ID
  "node_type": String,                      // 节点类型（可选）
  "sub_task_ids": [String],                 // 包含的子任务ID列表
  "dependencies": [String],                 // 前置依赖节点ID列表
  "status": Int32,                          // 节点状态（枚举）
  "created_at": Int64,                      // 创建时间
  "updated_at": Int64                       // 更新时间
}
```

### 5.2 字段说明

| 字段 | 类型 | 必填 | 说明 | 约束 |
|------|------|------|------|------|
| `node_id` | String | 是 | 节点唯一标识 | UUID格式，唯一索引 |
| `task_id` | String | 是 | 所属任务ID | 关联tasks表，索引 |
| `node_type` | String | 否 | 节点类型 | synthesis/case/report |
| `sub_task_ids` | Array | 是 | 子任务ID列表 | 至少包含1个 |
| `dependencies` | Array | 否 | 依赖节点列表 | synthesis节点为空 |
| `status` | Int32 | 是 | 节点状态 | 枚举值：0-4 |
| `created_at` | Int64 | 是 | 创建时间 | Unix秒级时间戳 |
| `updated_at` | Int64 | 是 | 更新时间 | Unix秒级时间戳 |

### 5.3 节点类型说明

| 类型 | 说明 |
|------|------|
| `synthesis` | synthesis阶段节点 |
| `case` | case节点（包含inference+eval子任务） |
| `report` | report阶段节点 |

### 5.4 索引设计

| 索引名 | 字段 | 类型 | 说明 |
|--------|------|------|------|
| `idx_node_id` | `node_id` | 唯一 | 业务主键查询 |
| `idx_task_id` | `task_id` | 普通 | 按任务查询节点列表 |
| `idx_task_status` | `task_id` + `status` | 复合 | 按任务和状态查询（DAG调度高频使用） |
| `idx_status` | `status` | 普通 | 查询Blocked节点（调度监控使用） |

## 七、查询场景分析

### 7.1 tasks 表查询场景

| 场景 | 查询条件 | 使用索引 |
|------|----------|----------|
| 任务详情查询 | `task_id` | `idx_task_id` |
| 任务列表查询 | `app_id` + `status` + 排序 | `idx_app_status` + `idx_created_at` |
| 任务状态监控 | `status` ∈ {Running, Waiting, Exception} | `idx_status_updated` |
| 过期数据清理 | `expired_at` < 当前时间 | 全表扫描（低频） |

### 7.2 subtasks 表查询场景

| 场景 | 查询条件 | 使用索引 |
|------|----------|----------|
| 子任务详情查询 | `sub_task_id` | `idx_sub_task_id` |
| 任务子任务列表 | `task_id` | `idx_task_id` |
| 执行服务负载查询 | `executor` + `status` ∈ {Allocated, Running} | `idx_executor_status` |
| 异常子任务查询 | `status` = Exception | `idx_status` |

### 7.3 dag_nodes 表查询场景

| 场景 | 查询条件 | 使用索引 |
|------|----------|----------|
| 节点详情查询 | `node_id` | `idx_node_id` |
| 任务DAG查询 | `task_id` | `idx_task_id` |
| Blocked节点监控 | `status` = Blocked | `idx_status` |
| 依赖检查查询 | `node_id` ∈ dependencies | `idx_node_id` |

## 八、原子操作设计

### 8.1 状态原子更新

**DAGNode状态更新**：

```javascript
// 从Blocked更新为Ready（需检查依赖）
db.dag_nodes.updateOne(
  {
    "node_id": "node-002",
    "status": 0  // 确保当前状态为Blocked
  },
  {$set: {"status": 1, "updated_at": 1761983700}}
)
```

**SubTask状态更新**：

```javascript
// 从Allocated更新为Running（需检查当前状态）
db.subtasks.updateOne(
  {
    "sub_task_id": "subtask-001",
    "status": 1  // 确保当前状态为Allocated
  },
  {$set: {"status": 2, "updated_at": 1761983700}}
)
```

### 8.2 重试计数原子更新

```javascript
// 重试计数递增
db.subtasks.updateOne(
  {"sub_task_id": "subtask-001"},
  {
    $inc: {"retry_count": 1},
    $set: {"status": 5, "updated_at": 1761983700}
  }
)
```

### 8.3 Master心跳原子更新

```javascript
// Master心跳更新（带角色校验）
db.master_state.updateOne(
  {
    "node_id": "scheduler-node-01",
    "role": "master"  // 确保自己是master
  },
  {$set: {"last_heartbeat": 1761983700, "updated_at": 1761983700}}
)
```

## 九、事务设计

### 9.1 任务创建事务

创建任务时，需同时写入Task、DAGNode、SubTask记录：

```javascript
session.startTransaction()

try {
  db.tasks.insertOne(taskDoc, {session})
  db.dag_nodes.insertMany(nodeDocs, {session})
  db.subtasks.insertMany(subtaskDocs, {session})
  session.commitTransaction()
} catch (error) {
  session.abortTransaction()
  throw error
}
```

### 9.2 任务取消事务

取消任务时，需联动更新Task、SubTask、DAGNode状态：

```javascript
session.startTransaction()

try {
  db.tasks.updateOne(
    {"task_id": taskId, "status": {$in: [0, 1, 5]}},
    {$set: {"status": 4, "updated_at": now}},
    {session}
  )
  db.subtasks.updateMany(
    {"task_id": taskId, "status": {$in: [0, 1, 2]}},
    {$set: {"status": 6, "updated_at": now}},
    {session}
  )
  db.dag_nodes.updateMany(
    {"task_id": taskId, "status": {$in: [0, 1, 2]}},
    {$set: {"status": 4, "updated_at": now}},
    {session}
  )
  session.commitTransaction()
} catch (error) {
  session.abortTransaction()
  throw error
}
```

## 十、数据生命周期

### 10.1 数据保留策略

| 数据类型 | 保留周期 | 说明 |
|----------|----------|------|
| Finished/Failed任务 | 7天 | 用户查询报告后可清理 |
| Canceled任务 | 3天 | 取消任务快速清理 |
| Running任务数据 | 不清理 | 任务执行期间保留 |
| SubTask/DAGNode | 与Task同步清理 | 随任务一起清理 |
| MasterState | 永久保留 | 调度服务运行期间保留 |

### 10.2 清理机制

```javascript
// 清理过期的已完成任务
db.tasks.deleteMany({
  "status": {$in: [2, 3, 4]},
  "expired_at": {$lt: Date.now() / 1000}
})

// 清理对应的SubTask
db.subtasks.deleteMany({
  "task_id": {$in: deletedTaskIds}
})

// 清理对应的DAGNode
db.dag_nodes.deleteMany({
  "task_id": {$in: deletedTaskIds}
})
```
