# 数据模型详细设计文档

## 一、概述

### 1.1 文档目的

本文档详细定义应用评测服务（agent-eval-server）的 MongoDB 数据模型，包括：
- 各 Collection 的表结构设计
- 字段类型与约束定义
- 索引设计
- 查询场景分析
- 数据示例

### 1.2 设计原则

| 原则 | 说明 |
|------|------|
| **一致性** | 字段命名与架构文档 Go 结构体保持一致 |
| **可扩展** | 预留扩展字段，使用 BSON 嵌入文档支持灵活配置 |
| **高性能** | 索引覆盖高频查询场景，避免全表扫描 |
| **并发安全** | 关键状态字段支持原子更新，避免竞态条件 |

### 1.3 数据库概述

| Collection | 说明 | 主要操作 |
|------------|------|----------|
| `tasks` | 任务记录 | CRUD、状态更新、进度查询 |
| `subtasks` | 子任务记录 | 创建、状态更新、按任务查询 |
| `dag_nodes` | DAG节点记录 | 创建、状态更新、依赖查询 |
| `master_state` | 主从状态 | 心跳更新、角色切换 |

## 二、tasks 表设计

### 2.1 表结构

```javascript
{
  "_id": ObjectId,           // MongoDB自动生成
  "task_id": String,         // 任务唯一标识（业务主键）
  "app_id": String,          // 应用标识
  "description": String,     // 任务描述
  "config": {                // 任务配置（嵌入文档）
    "version": String,       // 配置版本
    "workflow": [String],    // 执行阶段列表
    "models": [{             // 模型配置列表
      "id": String,          // 模型ID
      "type": String,        // 模型类型
      "api_key": String,     // API密钥
      "api_url": String,     // API地址
      "model": String,       // 模型名称
      "concurrency": Int32   // 并发数
    }],
    "synthesis": {           // synthesis阶段配置
      "type": String,
      "count": Int32,
      "model": String
    },
    "inference": {           // inference阶段配置
      "type": String,
      "model": String,
      "merge_eval": Boolean
    },
    "eval": {                // eval阶段配置
      "model": String
    },
    "report": {              // report阶段配置
      "type": String,
      "model": String
    }
  },
  "resources_ref": {         // 资源引用（嵌入文档）
    "skills_stored": Boolean,  // skills是否已存储
    "files_stored": Boolean,   // files是否已存储
    "storage_type": String     // 存储类型：mongodb/s3
  },
  "status": Int32,           // 任务状态（枚举）
  "progress": Int32,         // 执行进度 0-100
  "message": String,         // 状态消息
  "result": {                // 评测结果汇总（嵌入文档）
    "report_url": String,    // 评测报告URL
    "usages": [{             // Token消耗统计
      "model_id": String,
      "input_tokens": Int64,
      "output_tokens": Int64
    }],
    "conclusion": {          // 评测结论
      "score": Double,
      "summary": String,
      "details": [Object]
    }
  },
  "created_at": Int64,       // 创建时间（Unix时间戳）
  "updated_at": Int64,       // 更新时间（Unix时间戳）
  "expired_at": Int64        // 过期时间（Unix时间戳，可选）
}
```

### 2.2 字段说明

| 字段 | 类型 | 必填 | 说明 | 约束 |
|------|------|------|------|------|
| `task_id` | String | 是 | 任务唯一标识 | UUID格式，唯一索引 |
| `app_id` | String | 是 | 应用标识 | 用于权限校验，索引 |
| `description` | String | 否 | 任务描述 | 最大500字符 |
| `config` | Object | 是 | 任务配置嵌入文档 | 必须包含workflow字段 |
| `resources_ref` | Object | 否 | 资源存储引用 | 大文件可存外部存储 |
| `status` | Int32 | 是 | 任务状态 | 枚举值：0-5 |
| `progress` | Int32 | 是 | 执行进度 | 0-100 |
| `message` | String | 否 | 状态消息 | 最大200字符 |
| `result` | Object | 否 | 评测结果 | 仅完成状态填充 |
| `created_at` | Int64 | 是 | 创建时间 | Unix秒级时间戳 |
| `updated_at` | Int64 | 是 | 更新时间 | Unix秒级时间戳 |
| `expired_at` | Int64 | 否 | 过期时间 | 用于数据清理 |

### 2.3 状态枚举

| 值 | 名称 | 说明 |
|----|------|------|
| 0 | Waiting | 等待中（DAG节点未释放） |
| 1 | Running | 执行中（有子任务正在执行） |
| 2 | Finished | 执行完成 |
| 3 | Failed | 任务失败 |
| 4 | Canceled | 任务取消 |
| 5 | Exception | 任务异常（中间态） |

### 2.4 索引设计

| 索引名 | 字段 | 类型 | 说明 |
|--------|------|------|------|
| `idx_task_id` | `task_id` | 唯一 | 业务主键查询 |
| `idx_app_id` | `app_id` | 普通 | 按应用查询任务列表 |
| `idx_app_status` | `app_id` + `status` | 复合 | 按应用和状态筛选任务 |
| `idx_created_at` | `created_at` | 普通 | 按时间排序查询 |
| `idx_status_updated` | `status` + `updated_at` | 复合 | 状态监控、过期清理 |

**索引创建语句**：

```javascript
// 唯一索引
db.tasks.createIndex({"task_id": 1}, {unique: true, name: "idx_task_id"})

// 单字段索引
db.tasks.createIndex({"app_id": 1}, {name: "idx_app_id"})
db.tasks.createIndex({"created_at": -1}, {name: "idx_created_at"})

// 复合索引
db.tasks.createIndex({"app_id": 1, "status": 1}, {name: "idx_app_status"})
db.tasks.createIndex({"status": 1, "updated_at": 1}, {name: "idx_status_updated"})
```

## 三、subtasks 表设计

### 3.1 表结构

```javascript
{
  "_id": ObjectId,           // MongoDB自动生成
  "sub_task_id": String,     // 子任务唯一标识（业务主键）
  "task_id": String,         // 所属任务ID
  "stage": String,           // 阶段类型
  "case_id": String,         // case标识（可选）
  "merge_mode": Boolean,     // 是否合并模式
  "config": {                // 子任务执行配置（嵌入文档）
    "model_config": {        // 模型配置
      "id": String,
      "type": String,
      "api_key": String,
      "api_url": String,
      "model": String,
      "concurrency": Int32
    },
    "stage_config": Object,  // 阶段配置（动态结构）
    "evalset_ref": {         // 评测集引用（可选）
      "evalset_id": String,
      "app_id": String
    }
  },
  "status": Int32,           // 子任务状态（枚举）
  "executor": String,        // 执行服务地址
  "sandbox_id": String,      // 沙箱session_id
  "result": {                // 执行结果（嵌入文档）
    "success": Int32,        // 执行结果：-1失败/0执行中/1完成
    "message": String,       // 执行消息
    "output_files": {        // 输出文件路径
      "transcript.jsonl": String,
      "evalset.jsonl": String
    },
    "usage": {               // Token消耗
      "model_id": String,
      "input_tokens": Int64,
      "output_tokens": Int64
    }
  },
  "retry_count": Int32,      // 重试次数
  "created_at": Int64,       // 创建时间
  "updated_at": Int64        // 更新时间
}
```

### 3.2 字段说明

| 字段 | 类型 | 必填 | 说明 | 约束 |
|------|------|------|------|------|
| `sub_task_id` | String | 是 | 子任务唯一标识 | UUID格式，唯一索引 |
| `task_id` | String | 是 | 所属任务ID | 关联tasks表，索引 |
| `stage` | String | 是 | 阶段类型 | 枚举：synthesis/inference/eval/report |
| `case_id` | String | 否 | case标识 | inference/eval阶段必填 |
| `merge_mode` | Boolean | 否 | 合并模式标记 | 默认false |
| `config` | Object | 是 | 执行配置嵌入文档 | 从TaskConfig提取 |
| `status` | Int32 | 是 | 子任务状态 | 枚举值：0-6 |
| `executor` | String | 否 | 执行服务地址 | 分配后填充 |
| `sandbox_id` | String | 否 | 沙箱session_id | 执行后填充 |
| `result` | Object | 否 | 执行结果 | 完成后填充 |
| `retry_count` | Int32 | 是 | 重试次数 | 默认0，最大3 |
| `created_at` | Int64 | 是 | 创建时间 | Unix秒级时间戳 |
| `updated_at` | Int64 | 是 | 更新时间 | Unix秒级时间戳 |

### 3.3 状态枚举

| 值 | 名称 | 说明 |
|----|------|------|
| 0 | Waiting | 等待调度 |
| 1 | Allocated | 已分配执行服务 |
| 2 | Running | 运行中 |
| 3 | Finished | 完成 |
| 4 | Failed | 失败 |
| 5 | Exception | 异常（可重试） |
| 6 | Canceled | 取消 |

### 3.4 索引设计

| 索引名 | 字段 | 类型 | 说明 |
|--------|------|------|------|
| `idx_sub_task_id` | `sub_task_id` | 唯一 | 业务主键查询 |
| `idx_task_id` | `task_id` | 普通 | 按任务查询子任务列表 |
| `idx_task_stage` | `task_id` + `stage` | 复合 | 按任务和阶段查询 |
| `idx_status` | `status` | 普通 | 状态监控查询 |
| `idx_executor_status` | `executor` + `status` | 复合 | 执行服务负载查询 |

**索引创建语句**：

```javascript
// 唯一索引
db.subtasks.createIndex({"sub_task_id": 1}, {unique: true, name: "idx_sub_task_id"})

// 单字段索引
db.subtasks.createIndex({"task_id": 1}, {name: "idx_task_id"})
db.subtasks.createIndex({"status": 1}, {name: "idx_status"})

// 复合索引
db.subtasks.createIndex({"task_id": 1, "stage": 1}, {name: "idx_task_stage"})
db.subtasks.createIndex({"executor": 1, "status": 1}, {name: "idx_executor_status"})
```

## 四、dag_nodes 表设计

### 4.1 表结构

```javascript
{
  "_id": ObjectId,           // MongoDB自动生成
  "node_id": String,         // 节点唯一标识（业务主键）
  "task_id": String,         // 所属任务ID
  "node_type": String,       // 节点类型：synthesis/case/report
  "sub_task_ids": [String],  // 包含的子任务ID列表
  "dependencies": [String],  // 前置依赖节点ID列表
  "status": Int32,           // 节点状态（枚举）
  "created_at": Int64,       // 创建时间
  "updated_at": Int64        // 更新时间
}
```

### 4.2 字段说明

| 字段 | 类型 | 必填 | 说明 | 约束 |
|------|------|------|------|------|
| `node_id` | String | 是 | 节点唯一标识 | UUID格式，唯一索引 |
| `task_id` | String | 是 | 所属任务ID | 关联tasks表，索引 |
| `node_type` | String | 是 | 节点类型 | 枚举：synthesis/case/report |
| `sub_task_ids` | Array | 是 | 子任务ID列表 | 至少包含1个 |
| `dependencies` | Array | 否 | 依赖节点列表 | synthesis节点为空 |
| `status` | Int32 | 是 | 节点状态 | 枚举值：0-4 |
| `created_at` | Int64 | 是 | 创建时间 | Unix秒级时间戳 |
| `updated_at` | Int64 | 是 | 更新时间 | Unix秒级时间戳 |

### 4.3 状态枚举

| 值 | 名称 | 说明 |
|----|------|------|
| 0 | Blocked | 阻塞（依赖节点未完成） |
| 1 | Ready | 就绪（依赖节点已完成，可调度） |
| 2 | Running | 运行中（子任务正在执行） |
| 3 | Finished | 完成（所有子任务完成） |
| 4 | Failed | 失败（有子任务失败） |

### 4.4 索引设计

| 索引名 | 字段 | 类型 | 说明 |
|--------|------|------|------|
| `idx_node_id` | `node_id` | 唯一 | 业务主键查询 |
| `idx_task_id` | `task_id` | 普通 | 按任务查询节点列表 |
| `idx_task_status` | `task_id` + `status` | 复合 | 按任务和状态查询（DAG调度高频使用） |
| `idx_status` | `status` | 普通 | 查询Blocked节点（调度监控使用） |

**索引创建语句**：

```javascript
// 唯一索引
db.dag_nodes.createIndex({"node_id": 1}, {unique: true, name: "idx_node_id"})

// 单字段索引
db.dag_nodes.createIndex({"task_id": 1}, {name: "idx_task_id"})
db.dag_nodes.createIndex({"status": 1}, {name: "idx_status"})

// 复合索引
db.dag_nodes.createIndex({"task_id": 1, "status": 1}, {name: "idx_task_status"})
```

## 六、查询场景分析

### 6.1 tasks 表查询场景

| 场景 | 查询条件 | 使用索引 | 说明 |
|------|----------|----------|------|
| 任务提交查询 | `task_id` | `idx_task_id` | 唯一索引，单条查询 |
| 任务列表查询 | `app_id` + `status` + 排序 | `idx_app_status` + `idx_created_at` | 分页查询 |
| 任务状态监控 | `status` ∈ {Running, Waiting} | `idx_status_updated` | 监控活跃任务 |
| 过期数据清理 | `expired_at` < 当前时间 | 全表扫描（低频） | 定时任务清理 |

**典型查询语句**：

```javascript
// 查询任务详情
db.tasks.findOne({"task_id": "agent-eval-abc123"})

// 查询应用的运行中任务列表（分页）
db.tasks.find({
  "app_id": "agent-eval-app",
  "status": {$in: [0, 1]}
}).sort({"created_at": -1}).skip(0).limit(20)

// 查询需要监控的活跃任务
db.tasks.find({
  "status": {$in: [0, 1, 5]}
}).sort({"updated_at": 1})
```

### 6.2 subtasks 表查询场景

| 场景 | 查询条件 | 使用索引 | 说明 |
|------|----------|----------|------|
| 子任务详情查询 | `sub_task_id` | `idx_sub_task_id` | 唯一索引，单条查询 |
| 任务子任务列表 | `task_id` + `stage` | `idx_task_stage` | 按任务查询 |
| 执行服务负载查询 | `executor` + `status` ∈ {Allocated, Running} | `idx_executor_status` | 负载均衡使用 |
| 异常子任务查询 | `status` = Exception | `idx_status` | 重试调度使用 |

**典型查询语句**：

```javascript
// 查询子任务详情
db.subtasks.findOne({"sub_task_id": "subtask-001"})

// 查询任务的所有子任务
db.subtasks.find({"task_id": "agent-eval-abc123"})

// 查询执行服务的活跃子任务数
db.subtasks.countDocuments({
  "executor": "executor-01:8081",
  "status": {$in: [1, 2]}
})

// 查询需要重试的异常子任务
db.subtasks.find({
  "status": 5,
  "retry_count": {$lt: 3}
})
```

### 6.3 dag_nodes 表查询场景

| 场景 | 查询条件 | 使用索引 | 说明 |
|------|----------|----------|------|
| 节点详情查询 | `node_id` | `idx_node_id` | 唯一索引，单条查询 |
| 任务DAG查询 | `task_id` | `idx_task_id` | 获取完整DAG |
| Blocked节点监控 | `status` = Blocked | `idx_status` | DAG调度高频使用 |
| 依赖检查查询 | `node_id` ∈ dependencies | `idx_node_id` | 批量查询依赖节点状态 |

**典型查询语句**：

```javascript
// 查询节点详情
db.dag_nodes.findOne({"node_id": "node-001"})

// 查询任务的所有DAG节点
db.dag_nodes.find({"task_id": "agent-eval-abc123"})

// 查询Blocked状态的节点（DAG调度使用）
db.dag_nodes.find({"status": 0})

// 批量查询依赖节点状态
db.dag_nodes.find({
  "node_id": {$in: ["node-001", "node-002"]}
})
```

## 八、事务设计

### 8.1 任务创建事务

创建任务时，需同时写入Task、DAGNode、SubTask记录：

```javascript
// 事务伪代码
session.startTransaction()

try {
  // 1. 插入Task记录
  db.tasks.insertOne(taskDoc, {session})

  // 2. 插入DAGNode记录（批量）
  db.dag_nodes.insertMany(nodeDocs, {session})

  // 3. 插入SubTask记录（批量）
  db.subtasks.insertMany(subtaskDocs, {session})

  session.commitTransaction()
} catch (error) {
  session.abortTransaction()
  throw error
}
```

### 8.2 任务取消事务

取消任务时，需联动更新Task、SubTask状态：

```javascript
// 事务伪代码
session.startTransaction()

try {
  // 1. 更新Task状态
  db.tasks.updateOne(
    {"task_id": taskId, "status": {$in: [0, 1, 5]}},
    {$set: {"status": 4, "updated_at": now}},
    {session}
  )

  // 2. 更新SubTask状态
  db.subtasks.updateMany(
    {"task_id": taskId, "status": {$in: [0, 1, 2]}},
    {$set: {"status": 6, "updated_at": now}},
    {session}
  )

  // 3. 更新DAGNode状态
  db.dag_nodes.updateMany(
    {"task_id": taskId, "status": {$in: [0, 1, 2]}},
    {$set: {"status": 4, "updated_at": now}},
    {session}
  )

  session.commitTransaction()
} catch (error) {
  session.abortTransaction()
  throw error
}
```

## 九、数据生命周期

### 9.1 数据保留策略

| 数据类型 | 保留周期 | 说明 |
|----------|----------|------|
| Finished/Failed任务 | 7天 | 用户查询报告后可清理 |
| Canceled任务 | 3天 | 取消任务快速清理 |
| Running任务数据 | 不清理 | 任务执行期间保留 |
| SubTask/DAGNode | 与Task同步清理 | 随任务一起清理 |
| MasterState | 永久保留 | 调度服务运行期间保留 |

})

// 清理对应的SubTask
db.subtasks.deleteMany({
  "task_id": {$in: deletedTaskIds}
